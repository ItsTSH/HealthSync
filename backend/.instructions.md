# HealthSync RAG - Implementation Prompt for Claude Haiku 4.5

## Context
HealthSync is a medical notes RAG system with production-grade LLM integration. **Phases 1-4 complete** (infrastructure, services, endpoints). **Phases 5-6 pending** (testing, optimization, cleanup).

## Current Architecture
```
User Query → FastAPI /search/rag → Gemini Embed → pgvector Retrieve → 
Rerank (cross-encoder) → Groq LLM → Response with Citations
```

**Async Path:** `/process-note-async` → Celery → Background Embedding → pgvector Storage

## Completed Components
- ✅ 8 RAG services (chunking, masking, embeddings, retrieval, reranking, LLM, audit)
- ✅ 3 API endpoints (/search/rag, /process-note-async, /task-status)
- ✅ Celery task queue with Redis
- ✅ Supabase pgvector database schema with RLS
- ✅ 50+ configurable parameters

### 5.3 Performance Profiling
**Goal:** Establish latency baselines and optimize  
**Requirements:**
- Create `scripts/benchmark_rag.py` - Profile each pipeline stage (embed: ms, retrieve: ms, rerank: ms, LLM: ms)
- Create `scripts/load_test.py` - Concurrent query testing (10, 50, 100 simultaneous requests)
- Create `scripts/memory_profile.py` - Check for memory leaks in workers

**Acceptance Criteria:**
- Single query: <2 seconds (600ms embed + 300ms retrieve + 200ms rerank + 800ms LLM + 100ms overhead)
- Cache hit: <100ms
- 50 concurrent queries: <5 second p95

### 5.4 Error Handling Tests
**Goal:** Verify graceful degradation  
**Requirements:**
- Test Gemini API timeout → fallback to mock embeddings
- Test Groq API failure → return raw chunks without synthesis
- Test pgvector query failure → return empty results with error message
- Test Redis unavailable → skip caching, continue RAG
- Test RLS violation → return 403 Forbidden

## Implementation Standards

### Code Quality
- **Logging:** Use `import logging; logger = logging.getLogger(__name__)`
- **Errors:** Raise descriptive exceptions with context
- **Async:** Use `async def` for all I/O operations (database, APIs)
- **Types:** All function signatures must have type hints
- **Docstrings:** Google-style, include Args, Returns, Raises

### Testing
- **Pattern:** `def test_<function>_<scenario>() -> None:`
- **Mocking:** Mock external services (Gemini, Groq, Supabase)
- **Fixtures:** Use pytest fixtures for common setup (db, redis, config)
- **Assertions:** Clear, specific error messages
