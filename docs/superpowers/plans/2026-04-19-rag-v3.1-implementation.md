# RAG System v3.1 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement this plan task-by-task with continuous tracking.

**Goal:** Implement a production-grade, HIPAA-compliant RAG system matching RAG_DESIGN.md v3.1 specification with 12 advanced improvements including dual-storage architecture, deterministic PII masking, encrypted reference tables, BGE reranking, temporal weighting, multi-patient safety, and comprehensive audit logging.

**Architecture:** Multi-stage query pipeline with masked-only processing through embedding/retrieval/LLM layers, deterministic token generation for patient anonymization, post-generation token restoration from combined token maps, comprehensive audit logging with multi-patient flagging, and built-in PII leak detection. Dual-storage (masked + original) ensures retrieval quality while maintaining cryptographic security.

**Tech Stack:** FastAPI 0.120.0, PostgreSQL 15+ (Supabase pgvector), Gemini Embeddings API, Groq LLM (mixtral-8x7b), BGE Reranker (bge-reranker-base), AES-256-GCM encryption (cryptography lib), SQLAlchemy 2.0.44 ORM

**Timeline:** 5-7 days for full production-ready implementation

## Risk Mitigation

| Risk | Mitigation |
|------|-----------|
| **PII leaks in response** | Pre/post-generation leak detection, validation |
| **Token collision** | SHA256 with salt provides collision resistance |
| **Embedding API downtime** | Fallback to BM25 keyword search, caching |
| **Reranker unavailable** | Graceful fallback to similarity-only scoring |
| **LLM timeout** | Streaming partial response, timeout handlers |
| **RLS misconfiguration** | Comprehensive testing, audit log verification |
| **Performance degradation** | Latency monitoring, caching strategy, indexing |
